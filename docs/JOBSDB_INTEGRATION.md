# JobsDB 平台内直接更新（1.1）

日期：2026-10-08。本次按用户最新要求实现平台内直接采集，不读取或同步现有爬虫输出。原项目 `jobsdb-pipeline/crawler/jobsdb_crawler.py` 与 `jobsdb_job_details.py` 保持不变。

## 使用

启动 `main.py` 后访问 http://127.0.0.1:8765/。首页默认选择 JobsDB，数据工作台第一张卡片为 JobsDB 香港。输入关键词（可留空），选择每次更新数量并点击更新。页面显示列表／详情阶段、已处理数量和有效岗位数；可停止后续请求，刷新页面会继续观察当前后台任务。服务关闭会终止进程中的任务，已提交的数据库记录仍保存。

默认 50 条，可选 20、50、100、200；CLI 的 `--limit` 支持 1–200。更新按最新发布时间和所填关键词检索，继承原爬虫类别参数 `6281,1209,6123`，不是整个 JobsDB 全量岗位。一次最多两个列表请求、200 个详情请求，逐个请求间隔至少 1.5 秒，单请求超时 20 秒。跨任务尝试间隔至少 60 秒。

命令行：`python main.py --collect JobsDB --keyword Python --limit 20`。

## 代码结合方式

`jobcompass/jobsdb.py` 改编用户原代码的两阶段流程：先调用香港站搜索路径 `/api/jobsearch/v5/search` 获取 ID，再调用 `/graphql` 的 `jobDetails` 获取内容、公司、地区、薪资、发布时间及到期状态。列表同时兼容顶层 `id` 和 `solMetadata.jobId`。每次运行仅使用一个会话标识，固定应用 User-Agent；没有照搬随机浏览器身份、Cookie 轮换、追踪字段及联系方式查询。

详情沿用已有研究数据清洗器，去除 HTML 和常见联系方式文本。请求不携带简历、DeepSeek 密钥或本机文件。代码使用 Python 标准库及已有 HTTPS 封装，不依赖外部脚本的 pandas、日志或相对工作目录。

接口为 `POST /api/jobsdb/update`，请求体 `{ "limit": 50, "keyword": "Python" }`，返回任务 ID。`GET /api/tasks/<id>` 返回任务状态及进度；`POST /api/tasks/cancel` 接收任务 ID。请求继续使用现有 localhost Host、Origin 与自定义头校验。

## 数据与兼容

SQLite 自动增加 `expires_at`、`availability`、`last_live_checked` 三列。更新前本机数据库已备份在不进入源码包的 output 目录。已有 JobsDB 研究岗位匹配相同原站 URL 时复用旧 ID，保留其投递状态与备注；历史导入不降级已实时更新的记录。未出现在本次有限检索中的职位不会据此判为下线，也不会删除。

`isExpired=true` 或已到期日期会显示为已过期；界面默认隐藏，可取消筛选查看原记录。历史快照明确标记为尚未在线核实，在线结果显示最后读取时间。新数据库默认使用随附 2026-09-28 历史快照，便于离线运行；显式 `--demo` 才初始化 12 条虚构岗位。旧库中原有虚构岗位和补充来源仍保留。

## 失败与限制

HTTP 拒绝、限流、网络失败或 GraphQL 错误会停止此次采集，不轮换身份重试。若此前已有有效详情，则保存这些岗位并报告“部分完成”；若没有则报告失败。无效字段、ID 不符及无法取得详情的记录单独计数，不写入错误岗位。停止任务时也保存已完成的有效记录。

这两个网站内部接口并非稳定的官方开放招聘 API，未来字段、访问要求或可用性可能变化。接口可返回数据不代表获得再分发或批量采集许可。JobsDB 的 [robots.txt](https://hk.jobsdb.com/robots.txt) 当前列出了对这两个路径的自动抓取限制，使用与部署应限于获得允许的范围；本版本专用适配器未实现 robots 自动拦截。通用网页采集器的 robots 检查仍保留。结果仅用于求职辅助，申请前仍须在原站核实。
